# 02 — Backup، Restore و Point-in-Time Recovery

Backup بدون Restore تست‌شده، Backup قابل اعتماد نیست. هدف، داشتن نسخه‌ای مستقل و قابل‌بازیابی از داده است نه صرفاً کپی فایل.

Backup منطقی معمولاً خروجی Schema و Data در قالب SQL یا فرمت ابزار اختصاصی است؛ مزیت آن قابلیت انتقال و انتخاب‌پذیری است، ولی برای دیتابیس بسیار بزرگ کندتر است. Backup فیزیکی تصویر سطح فایل/Block از داده‌هاست و برای بازیابی سریع و PITR مناسب‌تر است.

Full Backup کل داده را ثبت می‌کند. Incremental فقط تغییرات از آخرین Backup را ذخیره می‌کند. Differential تغییرات از آخرین Full را نگه می‌دارد. راهبرد 3-2-1 یعنی حداقل سه نسخه، روی دو رسانه متفاوت و یک نسخه خارج از محل یا حساب اصلی.

PITR با ترکیب Base Backup و لاگ تغییرات مانند WAL/Binlog امکان بازگرداندن دیتابیس به لحظه‌ای قبل از خطای انسانی را می‌دهد. سناریوی استاندارد: Base Backup منظم + آرشیو پیوسته لاگ + Restore Drill.

چک‌لیست بازیابی: اعتبارسنجی checksum، تمرین Restore در محیط جدا، اندازه‌گیری RTO واقعی، ثبت وابستگی‌ها، نگهداری کلیدهای رمزنگاری و مستندسازی Runbook.

مثال PostgreSQL: `pg_dump` برای Backup منطقی، `pg_restore` برای بازیابی فرمت custom و WAL Archiving برای PITR استفاده می‌شود.
