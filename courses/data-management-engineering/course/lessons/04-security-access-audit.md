# 04 — رمزنگاری، کاربران، دسترسی و Audit Log

امنیت داده سه محور اصلی دارد: Confidentiality، Integrity و Availability. رمزنگاری فقط یکی از لایه‌هاست.

Encryption in Transit با TLS ارتباط Client و Database را محافظت می‌کند. Encryption at Rest برای دیسک، فایل Backup یا Storage استفاده می‌شود. کلید رمزنگاری نباید کنار داده و با همان سطح دسترسی نگهداری شود؛ KMS/HSM برای جداسازی کلیدها مناسب است.

مدیریت دسترسی باید بر اصل Least Privilege بنا شود. به‌جای اعطای مستقیم مجوز به افراد، Role تعریف کنید؛ Roleهای Reader، Writer، Migration و Admin را جدا نگه دارید. حساب سرویس اپلیکیشن نباید مجوز DDL یا Superuser داشته باشد.

Audit Log باید مشخص کند چه کسی، چه زمانی، روی چه داده‌ای، چه عملی انجام داده و نتیجه چه بوده است. Audit با Log عادی متفاوت است: هدف آن قابلیت پاسخ‌گویی، ممیزی و کشف سوءاستفاده است. برای داده حساس، دسترسی‌های موفق و ناموفق، تغییر Role، DDL و عملیات Export را ثبت کنید.

نکته: ذخیره رمز عبور باید با Hash مقاوم مانند Argon2/bcrypt انجام شود؛ رمز عبور را با Encryption قابل برگشت نگهداری نکنید.
